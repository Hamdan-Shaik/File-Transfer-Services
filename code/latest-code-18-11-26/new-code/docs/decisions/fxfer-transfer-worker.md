- File transfer protocols: legacy EnterpriseDT.Net.Ftp types are shimmed over OSS clients (FluentFTP for FTP/FTPS, SSH.NET for SFTP) to preserve the target method signatures without adopting the commercial edtFTPnetPRO runtime.
- Notifications lookup: GetNotificationSearchCriteria in the new worker contracts requires a Guid ConfigId; legacy SendNotification(long configId, ...) did not set a config filter, so this port preserves that and uses only NotifyOnErrorInd/NotifyOnSuccessInd flags to emulate legacy in-code filtering.
- Legacy LoggerManager: replaced with injected Microsoft.Extensions.Logging.ILogger to match the worker runtime and OpenTelemetry logging stack.
- FtsSuspensionSearchCriteria: legacy OperatorId field is not present in the new contract type, so HandleLocationException records SourceLocationId + error text/stack only.
- IsSourceSetToRun unsuspension: legacy GetSuspendedLocation + update-by-entity is not available in the new data-access contract, so the port clears suspension via UpdateSourceSuspendStatusDataAccess(sourceLocationId).
- Excluded extensions: the legacy ExcludedFileExtensions enum is ported into Fxfer.TransferWorker.Domain.Exceptions to preserve Enum.IsDefined checks during source file discovery.
- SendNotification behavior/signature: supersedes prior notification-recipient lookup decision; part-4 brief requires emailing only SourceLocation owner (OwnerEmail/OwnerName) and passing tenantId explicitly.
- SSH private key path: legacy AssemblyName.CodeBase/Substring(6) replaced with AppContext.BaseDirectory + FileTransferManagementConstants.Paths.PathToPrivateKeyFile for .NET compatibility.
- RsaSha256Util: implemented as a no-op helper, relying on SSH.NET 2024 RSA-SHA2 support.
- backend-file-transfer-mgmt-ctrl placement: moved FileTransferSvc*Provider adapters to `workers/fxfer-transfer-worker/src/Application/Adapters` and their interfaces to `workers/fxfer-transfer-worker/src/Domain/Adapters` to follow the brief roles + checker, despite technical/components/backend-file-transfer-mgmt-ctrl/TARGET.md listing src/Infrastructure/Adapters.
- SharpZipLib CRC32 namespace: legacy references `ICSharpCode.SharpZipLib.Checksums.Crc32`; target SharpZipLib 1.4.2 exposes `ICSharpCode.SharpZipLib.Checksum.Crc32`, so the port uses that type.
- backend-file-transfer-mgmt-business layer placement: architecture.yaml maps this component to `workers/fxfer-transfer-worker/src/Application`, so the domain-marked interfaces remain under `workers/fxfer-transfer-worker/src/Application/Batch`.
- Nullability annotations: legacy contracts return `string` even when implementations can return null (e.g., UploadFile/UploadToUnc); port preserves the legacy signature for parity under `Nullable=enable`.
- run-file-transfer-batch CLI surface: added explicit `run-file-transfer-batch-basic`/`run-file-transfer-batch-managed` subcommands in `workers/fxfer-transfer-worker/src/Worker/CliEntrypoint.cs` and kept the legacy GUID-shaped invocation routed to the managed runner.
- run-file-transfer-batch acceptance coverage: copied `business/run-file-transfer-batch.feature` into `workers/fxfer-transfer-worker/test/Fxfer.TransferWorker.Tests/Specs/` unchanged and implemented the scenarios as xUnit flow tests (same pattern as other `*.feature`-paired `*FlowTests.cs` in this repo).
- DataAccessBase session/context: TARGET.md drops CreateDbSession/CreateDbContext (no direct DB access), so DataAccessBase.ExecuteAsync directly calls ExecuteQueryAsync(CancellationToken) using injected IFxferDomainApiClient/IRequestContextAccessor.
- Data access type placement: TARGET.md lists `workers/fxfer-transfer-worker/src/Infrastructure/DataAccess` for core data-access types, but brief roles + existing project place IDataAccess/DataAccessBase/DataAccessFactory under `workers/fxfer-transfer-worker/src/Application/DataAccess`; kept there to avoid cross-layer namespace churn.
